# Version 2: cited claim verification under controlled evidence conditions

Status: experiment implemented and software-tested; model outcomes are unmeasured.
The completed version-1 test remains a negative/mixed result and must be retained.

## Why this is a more useful research question

Instead of asserting that generic self-review improves six unrelated tasks, ask:
**Does cited verification help a small local model distinguish support,
contradiction and insufficient evidence when evidence selection changes?**

The intended contribution is a reproducible empirical comparison of evidence
conditions, citation fidelity, answer quality and cost in vulnerability claims.
This is a narrower, testable direction, not an invented claim of algorithmic
novelty or a guarantee of publication. Relevant prior work already studies
retrieval critique and citations:

- Self-RAG (Asai et al., ICLR 2024): https://arxiv.org/abs/2310.11511
- Corrective RAG (Yan et al., 2024): https://arxiv.org/abs/2401.15884
- ALCE (Gao et al., EMNLP 2023): https://aclanthology.org/2023.emnlp-main.398/
- SECURE (Bhusal et al., ACSAC 2024): https://doi.org/10.1109/ACSAC63791.2024.00019

No Self-RAG training, CRAG web-search system, or ALCE evaluator is reproduced.
The code uses the supplied SECURE CVE records and existing lexical ranker.
Selecting chunks from a known record is within-record evidence selection,
not an open-web retrieval benchmark.

## Data and exposure boundaries

Only the existing **validation split** is used: 53 KCV claims and their 53 VOOD
partners, from **14 source groups**. These are for development and method
selection. They are not 265 independent claims or a new untouched test.

Each KCV claim yields five evidence conditions, 53 cases each:

| Condition | Evidence supplied | Expected label and interpretation |
|---|---|---|
| Full record | All scalar fields, with JSON paths and stable passage IDs | Original KCV label |
| Missing | No record, matching the paired VOOD task | Original VOOD X |
| BM25 top 3 | Three highest-ranked chunks of the original record | Original KCV label; end-to-end performance, not proof that the retained evidence is sufficient |
| Unrelated | Lexically similar passages only from other development CVEs | Constructed X under the stated evidence boundary |
| Mixed | Full original record plus three unrelated passages | Original KCV label |

All full-record facts are retained by the existing path-aware chunker, including
oversized values. Chunks are at most 1,200 characters. Retrieval uses only the
claim text, with top-k=3 fixed before this run; no answer label chooses evidence.
Distractors come exclusively from development sources, not the observed test
or these validation sources. Literal passage IDs are content/source hashes.
BM25 query terms are summed in sorted order so process hash randomization
cannot change floating-point tie behavior during data preparation.

The 265 condition cases are repeated measurements of the same 53 claims.
Intervals resample source groups, preserving those dependencies. Fourteen
groups give limited precision. Constructed missing/unrelated cases are controlled
stress conditions, not naturally occurring unknown vulnerabilities.

## Compared stages

| Stage | Cases | Purpose |
|---|---:|---|
| Official prompt | Full record + missing (106) | Matched original-prompt reference |
| Format control | Full record + missing (106) | Explicit evidence-boundary definitions, same passages, JSON verdict only |
| Cited answer | All conditions (265) | Model verdict, exact quote, passage ID, comparison and self-reported confidence |
| Verifier | All conditions (265) | Model rechecks the cited attempt using the same supplied evidence |

Total: **742 calls**. The two-pair quick check makes **28 calls** and checkpoints
them for resuming. It estimates remaining time from condition/stage samples;
latencies can change with longer inputs and machine load.

The format control changes evidence representation and boundary instructions
relative to official prompts. Cited answers add both evidence reasoning and
citation fields. Those bundles are not pure single-variable causal ablations.
The verifier comparison isolates adding a second pass to that cited generator,
with greater compute. It uses the same model, so it is not independent verification.

Every verdict is generated by the model. There is no forced X routing, CVSS
answer comparator, gold-label lookup at inference, quote-based verdict override,
or hand-selected answer correction. Expected labels for constructed conditions
are scoring targets, not model predictions.

Primary model: the installed Qwen2.5 3B Instruct; another installed model can
be passed separately for replication. Each call has temperature 0.7, seed
20261101, 512 output tokens and a requested 32,768-token context window.
Model digest, full request/response, code hashes and settings are frozen.
An oversized input fails rather than intentionally dropping evidence. Model
format failures are saved and scored; they are not retried until valid.

## Evaluation and honest interpretation

Report per-condition accuracy, invalid count, binary answer rate, binary-answer
accuracy, predicted labels and paired stage gains/regressions with 95% source
cluster bootstrap intervals (2,000 samples). Missing and unrelated binary-answer
rates measure unsupported answering under those constructed boundaries.

For cited binary answers, mechanically check that the named passage exists and
the quoted words occur in it, allowing only whitespace normalization. Report
that as **literal citation fidelity**, not citation correctness, factuality or
entailment. A valid quote can still be irrelevant or support the opposite verdict.
Model confidence slices at 0/50/70/90/100 show binary coverage and accuracy;
they are exploratory and not calibrated risk guarantees or deployed routing rules.

Completed runs create a deterministic 30-response citation audit sample (three
cases per condition, both cited and verifier outputs). Method names and gold
labels are omitted. Reviewers must actually judge quote-to-verdict entailment;
annotations remain null until performed. Do not invent reviewer scores.

Record input/output tokens, calls and wall time for every stage. Verifier cost
includes its cited first pass. Do not pool condition scores into a headline
number that treats the five repeated cases as independent evidence.

## Evidence needed for the three research goals

1. **Future usefulness:** identify whether accurate quotes, evidence selection
   and verification explain repeatable improvements or failures. Compare with
   existing work, archive raw outputs and publish negative conditions too.
2. **Trustworthiness:** require fewer unsupported answers without collapsing
   binary coverage, actual human entailment checks, error accounting and
   second-model/seed replication. A clean JSON object is insufficient.
3. **Improvement over SECURE:** first measure matched original-prompt differences
   on the same inputs/model. Published SECURE scores are historical context.
   Different examples, quantization, model age and scorers do not establish
   superiority over the original authors' work.

After choosing the method on validation, obtain a fresh, source-disjoint or
temporal test with independently checked labels and evidence, freeze the chosen
configuration, and evaluate once. The old test has already informed version 2;
a repeat on it is a disclosed post-test diagnostic, not a new generalization result.
Do not replace the version-1 results with selectively improved numbers.
